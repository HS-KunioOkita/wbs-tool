## 1. スタイル設計方針

本スタイルガイド全体を貫く方針を示す。HCD / UI・UX 設計書 1 章「UX 設計方針」をスタイル基盤として翻訳したもの。

- **デザイン言語の出発点**: プライマリペルソナ PER-001（個人 WBS 管理者・Excel 経験者・macOS デスクトップ環境）が日次で開く業務ツールである。視覚的トーンは**信頼性・情報密度高め・装飾最小限**を採る。装飾的グラフィック・余白の過剰拡張・トレンドアニメーションは持たない。ガントチャートの読み取りやすさ（タスクバー・依存線・期限超過の即時判別）を、装飾より優先する。
- **対象環境とサポート範囲**: 要件 NFR-003 により Chrome 最新版 × macOS（最新および 1 つ前のメジャー）× 1280×720 以上のデスクトップ PC のみを保証する。タッチ操作・モバイル・タブレット・iOS Safari・Firefox 等は保証対象外。これにより本ガイドは**デスクトップファースト**で記述し、レスポンシブは「1280 以上での内部レイアウト調整」のみを扱う（モバイル時のカード化等は対象外）。
- **カラーシステムの設計原則**:
  - ブランドカラー（`primary`）と意味カラー（`success / warning / danger / info`）を区別する。本ツールは独自ブランドを持たないため、`primary` は「青系（信頼・操作）」を機械的に採用し、意味カラーは業務ステータス（期限超過 = `danger`、完了 = `success` 等）に対応させる。
  - 中間階調（ニュートラル）はグレースケール 10 段階で生成し、テキスト・境界・背景・無効状態を段階的に展開する。
  - **ダークモードは本リリースで採用しない**（要件 NFR-003 にダークモード要件がなく、Chrome × macOS × 1280×720 の固定環境では明環境利用が前提）。トークン命名は将来のダークモード採用余地を残し、ロール名（`text.primary` / `surface` 等）で表現する（HEX を直接使う命名にしない）。
  - 色のみで意味を伝えない（HCD A11Y-001 を継承）。期限超過・成功・警告などの状態色には必ずアイコンまたはラベルを併用する。
- **タイポグラフィスケール**:
  - 日本語 UI を主とし、CJK 対応のサンセリフをフォントファミリ種別として採用する。英数字・日付・進捗値の数値は読み取り頻度が高いため、必要に応じて等幅または半角サンセリフへフォールバックする。
  - スケールは**実用ベースの 5 段階**（`heading.h1` / `h2` / `h3` + `body.md` / `body.sm`）。本ツールは画面数が少なく見出し階層を深くする要件がないため、`h4` 以降は持たない。
  - 本文既定サイズ: 14px（UI 内の操作密度を優先）。長文テキスト（タスク説明・プロジェクト説明の閲覧時）は 16px 相当の `body.lg` を別途持つ。
- **スペーシング原則**:
  - 基底単位 4px。スケールは 4 / 8 / 12 / 16 / 24 / 32 / 48px の **7 段階**を採用する。
  - 密度レベルは**コンフォート単一**（密度切替は要件外）。ガントチャート行の高さ・タスクツリーのインデント幅は本ガイドのスペーシングトークンを参照しつつ、画面詳細（UI-003）で具体配置を確定する。
- **コンポーネントの設計原則**:
  - プリミティブ（Button / Input / Select 等）とコンポジット（FormField / Modal / Toolbar 等）を区別する。プリミティブの組合せで表現可能なものは新規コンポーネント化しない（バリアント膨張の歯止め）。
  - ガントチャート関連の要素（タスクバー・依存線・タイムライン軸）はガントチャート専用の特殊コンポーネントとして CMP に登録し、再利用しないことを明示する（UI-003 専用 / UI-009 PDF 出力にも流用される）。
  - 新しいバリアントを追加するときは、本ガイドへの追記を必須とする。画面詳細側で**無断で新バリアントを発明しない**（10.3 で禁則を再掲）。
- **モーション原則**:
  - 過度な動きを抑制する。マイクロインタラクション（hover / focus 反応）は 100ms 程度、状態遷移（モーダル開閉・パネル展開）は 200ms 程度、ガントチャートのプレビュー → 確定描画は即時または 150ms 以内のフェード、を目安とする。
  - **`prefers-reduced-motion: reduce`** を尊重し、ユーザー設定で動きを抑制した環境では duration を 50ms 以下に短縮（実質無効化）する。
- **アクセシビリティ最低基準**:
  - **WCAG 2.1 AA 準拠**を目標とする（HCD A11Y-001 / A11Y-002 継承）。コントラスト比は通常テキスト 4.5:1、大型テキスト 3:1。フォーカスリングは常時表示で 2px 以上の太さで識別可能にする。
  - キーボード操作で全主要操作（タスク CRUD・依存関係 CRUD・フィルタ・粒度切替・依存線切替・PDF 出力）が完結できることを基準にする。ガントチャート上のドラッグ操作（UC-007）のキーボード代替手段は HCD RISK-004 / 本書 6.3 HO-I-001 で別途扱う。
  - 色のみで情報を伝えない（期限超過バー・進捗バー）。
- **ダークモード方針**: 採用しない（1 章前述）。トークン命名はロール名ベースで定義し、将来採用時に値差し替えで対応可能とする。
- **拡張ポリシー**:
  - 新規トークン・新規コンポーネントの追加は、画面詳細レビュー時に「他画面でも再利用するか」を判断し、再利用性があれば本ガイドに追記する（画面詳細 10.3 の `CAN-NNN` から昇格させる）。
  - 1 画面でしか使わない一回限りの視覚パターンは、画面詳細内にローカル記述するが、その旨を画面詳細の注意事項に明記する。
- **非対応環境**: 1280×720 未満の解像度、Chrome 以外のブラウザ、macOS 以外の OS、タッチデバイスは保証対象外。これらの環境で UI が崩れても本ガイドの対象外とする（要件 NFR-003）。

| DTK-082 | `border.thick` | 4px | 強い強調（通常は使わない） |

### 2.5 モーショントークン

| DTK-NNN | 論理名 | 値 | 主な用途 |
|---|---|---|---|
| DTK-090 | `motion.fast` | 100ms | hover / focus / press のマイクロインタラクション |
| DTK-091 | `motion.base` | 200ms | モーダル開閉・パネル展開・トースト出現 |
| DTK-092 | `motion.slow` | 400ms | スケルトン → 本表示の入れ替え（必要時のみ） |
| DTK-093 | `ease.standard` | cubic-bezier(0.4, 0.0, 0.2, 1) | 標準的なイージング |
| DTK-094 | `ease.decelerate` | cubic-bezier(0.0, 0.0, 0.2, 1) | 要素の進入（モーダル表示・トースト出現） |
| DTK-095 | `ease.accelerate` | cubic-bezier(0.4, 0.0, 1, 1) | 要素の離脱（モーダル閉鎖・トースト消去） |

メモ:
- `prefers-reduced-motion: reduce` 環境では全 duration を 50ms 以下に短縮する方針（実質無効化）。HCD A11Y-006 を継承。
- ガントチャート上のタスクバーのドラッグプレビュー → 確定描画は `motion.fast` を超えない（即時感を優先）。
- アニメーションの自動再生・点滅は禁止（HCD A11Y-006、WCAG 2.3.1 準拠）。

### 2.6 ブレークポイント

| DTK-NNN | 論理名 | 下限幅 | 主な対象 | コンテナ幅方針 | カラム数方針 |

- ダイアログ（UI-002 / UI-004 / UI-005 / UI-006 / UI-007）の幅は固定（具体値は画面詳細で個別指定）。ブレークポイントによる変化を持たない。

### 3.2 各コンポーネント仕様

主要な共通コンポーネントの詳細仕様を示す。プリミティブとコンポジット中心に記述し、ガント専用コンポーネント（CMP-030〜CMP-033）は UI-003 画面詳細で配置仕様と併せて確定する。

#### CMP-001 Button

- **概要**: 操作実行のためのプリミティブ。本ツールではリンクテキスト型の遷移を採用せず、ナビゲーション含めボタンに統一する。
- **用途・原則**: 「動作」と「遷移」の両方で使用する。`primary` は 1 画面 1 つを原則とし、複数表示する場合は主 CTA 以外は `secondary` または `ghost` に降ろす。
- **バリアント**:
  | バリアント名 | 役割・意味 | 使用 DTK | 用法制約 |
  |---|---|---|---|
  | `primary` | 主操作（保存・出力・適用） | DTK-001, DTK-002, DTK-003, DTK-023 | 1 画面 1 つを原則 |
  | `secondary` | 副操作（キャンセル・戻る） | DTK-010, DTK-011, DTK-020 | 数に上限なし |
  | `danger` | 破壊的操作の確定（削除実行） | DTK-006, DTK-024 | ConfirmDialog 内のみ使用 |
  | `ghost` | 軽い操作（ツールバー操作・閉じる近く） | 透明背景 + hover で DTK-009 | アイコン併用が多い |
- **サイズ**:
  | サイズ名 | パディング | フォント | 主な用途 |
  |---|---|---|---|
  | `sm` | 縦 DTK-061 / 横 DTK-062 | DTK-049 | ツールバー内・テーブル行内 |
  | `md` | 縦 DTK-062 / 横 DTK-063 | DTK-049 | 既定 |
  | `lg` | 縦 DTK-063 / 横 DTK-065 | DTK-046 | モーダル内の主 CTA |
- **状態**: `default / hover / active / focus / disabled / loading`。
  | 状態 | 視覚変化 | 備考 |
  |---|---|---|
  | `default` | DTK-001 + DTK-023 | primary の例 |
  | `hover` | DTK-002 + DTK-023 | DTK-090 で遷移 |
  | `active` | DTK-003 + DTK-023 | press 中 |
  | `focus` | フォーカスリング DTK-081 + DTK-027 | キーボード focus 時の常時表示 |
  | `disabled` | DTK-011 + DTK-022 | `cursor: not-allowed` |
  | `loading` | 内部に CMP-024 Spinner、ラベルは非表示または併記、disabled 相当 | 二重押下抑止（HCD UXI-009 / 全フォーム送信時の必須挙動） |
- **要素構成**: `icon-leading（任意） / label / icon-trailing（任意）`。アイコンのみは CMP-002 IconButton を使う。
- **入出力契約**: `onClick`。loading 中・disabled 中は発火しない。
- **アクセシビリティ**: ARIA ロール `button`（ネイティブ `<button>` の場合は不要）。フォーカスリング常時表示。Enter / Space で発火。disabled 時はフォーカスを取らない（aria-disabled を併用するか属性で disabled にするかは HO-I-003）。
- **レスポンシブ挙動**: 幅は内容に応じて可変が既定。モーダル内のフッタでは「右寄せ + キャンセル左 / 主 CTA 右」の配置を ConfirmDialog / Modal で固定（CMP-015 / CMP-028 が制御）。
- **使用可否の制約**: 「動作」と「遷移」の両方に使う。リンクとボタンを見た目で混同させない（テキストリンクは使わない）。

#### CMP-003 TextInput

- **概要**: 1 行の文字列入力。タスク名・プロジェクト名・担当者・フィルタ条件で使用。
- **用途・原則**: 入力種別ごとに別コンポーネントを作らず、TextInput を基本に統一する。
- **バリアント**: なし（サイズと状態で表現）。
- **サイズ**: `sm / md`。既定は `md`。
- **状態**: `default / hover / focus / disabled / readonly / invalid`。
  | 状態 | 視覚変化 |
  |---|---|
  | `default` | 境界 DTK-025、背景 DTK-017、テキスト DTK-020 |
  | `hover` | 境界 DTK-026 |
  | `focus` | 境界 DTK-027 + フォーカスリング DTK-081 |
  | `disabled` | 背景 DTK-009、テキスト DTK-022、境界 DTK-025、`cursor: not-allowed` |
  | `readonly` | 背景 DTK-009、テキスト DTK-020、境界 DTK-025（編集不可だが読み取り対象、HCD A11Y-006 の取消可能性は満たさない読み取り専用表示） |
  | `invalid` | 境界 DTK-006、`aria-invalid="true"` |
- **要素構成**: `prefix（任意） / input / suffix（任意） / clear-button（任意）`。
- **入出力契約**: `onChange / onBlur / onFocus`。
- **アクセシビリティ**: 必ず `<label>` と関連付ける（CMP-013 FormField が制御）。`aria-describedby` で CMP-012 HelperText / エラーメッセージと関連付ける。
- **レスポンシブ挙動**: 幅は親コンテナに従う。

#### CMP-006 DateInput

- **概要**: 日付の入力。開始日・期限・フィルタの日付範囲で使用。
- **用途・原則**: ネイティブの日付入力（`<input type="date">`）を基本とする方針（実装簡素化と HO-I-003 / アクセシビリティ）。代替実装は HO-I-003 で確定。
- **バリアント・サイズ・状態**: CMP-003 TextInput と同じパターン。
- **入出力契約**: `onChange / onBlur`。値の論理型は日付（YYYY-MM-DD）。
- **アクセシビリティ**: ネイティブ実装の場合は Chrome の日付ピッカーをそのまま利用。キーボード操作（Tab / 矢印 / Enter）はネイティブに従う。
- **特記**: フィルタの「開始日 from」と「開始日 to」の組では、from の値変更に応じて to の最小値を制約する動的挙動を CMP-013 FormField レベルで実装する。

#### CMP-013 FormField

- **概要**: Label + 入力コンポーネント + HelperText / エラーメッセージのセット。フォーム全体の一貫したレイアウトを担保する。
- **用途・原則**: フォーム内の入力は原則すべて FormField でラップする。Label なしの入力は禁止（A11Y）。
- **要素構成**: `label / required-mark / input-area / helper-or-error / hint-tooltip（任意）`。
- **必須マーク方針**: 必須項目には `*` 記号 + 「必須」のテキスト併用（色のみで伝えない）。任意項目は何も表示しない（「任意」と書かない方針 — 必須を強調する非対称表現で認知負荷を下げる）。
- **エラー表示位置**: 入力エリア直下にインライン表示。CMP-012 HelperText の error バリアントを使う。
- **入出力契約**: 内部の入力コンポーネントに準ずる。
- **アクセシビリティ**: Label と入力の関連付け、`aria-required`、`aria-invalid`、`aria-describedby` の整合を担保する。

#### CMP-015 Modal

- **概要**: モーダルダイアログ。UI-002 / UI-004 / UI-005 / UI-006 / UI-007 / 削除確認に使用。
- **バリアント**:
  | バリアント名 | 役割 | 用法制約 |
  |---|---|---|
  | `form` | フォーム入力（UI-002 / UI-004 / UI-005 / UI-006 / UI-007） | `primary` ボタンが保存・適用・出力 |
  | `confirm` | 確認ダイアログ（一般的な確認） | 主 CTA は中立的（secondary） |
  | `destructive-confirm` | 破壊的操作の確認（プロジェクト削除・タスク削除・依存削除） | 主 CTA は `danger`、影響範囲（連鎖削除件数等）を必ず表示。HCD UXI-007 / FB-008 を実装 |
- **要素構成**: `scrim / dialog-container / header（title + close-button） / body / footer（actions）`。
- **挙動**:
  - 背後に CMP-028 で定義する scrim DTK-028 を敷く。
  - Escape キーで閉じる（`destructive-confirm` ではキャンセル扱い）。
  - フォーカストラップを内部に持つ（タブが外に抜けない、A11Y 必須）。
  - 開閉アニメーションは DTK-091 + DTK-094 / DTK-095 を使用。
- **アクセシビリティ**: ARIA ロール `dialog`、`aria-labelledby` で title と関連、`aria-describedby` で body の主要説明と関連。開いた時点で初期フォーカスを最初のフォーカス可能要素（タイトル直下の入力 or 主操作ボタン）に移動。閉じた後はトリガ要素にフォーカスを戻す。
- **レスポンシブ挙動**: 1280×720 を最小として、ダイアログ幅は固定（UI-002 / UI-004 等で個別指定）。

#### CMP-021 Toast

- **概要**: 短時間の通知。削除完了・PDF 出力開始・エラー通知に使用。
- **バリアント**: `success / warning / error`。
- **要素構成**: `icon（種別アイコン） / message / close-button（任意） / action-button（任意、エラー時のリトライ等）`。
- **挙動**:
  - 出現位置はアプリ右下（固定。HO-D-001 で具体配置確定）。
  - 自動消去: `success` は 4 秒、`warning` / `error` は手動消去（ユーザーが閉じる）。
  - 同時表示は最大 3 件まで。古いものから消える。
- **アクセシビリティ**: ARIA ライブリージョン `polite`（success）/ `assertive`（error）を使い分け、スクリーンリーダーへ通知（A11Y 必須）。HCD FB-002〜FB-006 を実装。

#### CMP-023 EmptyState

- **概要**: 空状態の表示。「データがない」「フィルタで 0 件」「権限なし（本ツールでは該当なし）」を区別する。
- **バリアント**:
  | バリアント名 | 想定状況 | CTA |
  |---|---|---|
  | `no-data` | データが 1 件もない（プロジェクト 0 件・タスク 0 件） | 「新規作成」ボタンを直接配置（HCD UXI-006） |
  | `filtered-zero` | フィルタ条件に合致するデータがない | 「フィルタをクリア」ボタンを配置 |
  | `error` | データ取得失敗（ERR-006 等） | 「再読み込み」ボタンを配置 |
- **要素構成**: `icon（任意） / title / description / cta-button`。
- **アクセシビリティ**: スクリーンリーダーには状態が変わったことを通知（CMP-021 と同様 ARIA ライブリージョン併用 or フォーカス移動）。

#### CMP-028 ConfirmDialog

- **概要**: 破壊的操作の確認。プロジェクト削除・タスク削除・依存関係削除で使用。CMP-015 Modal の `confirm` / `destructive-confirm` バリアントを使う特殊な合成。
- **バリアント**:
  | バリアント名 | 用途 | 強調レベル |
  |---|---|---|
  | `default` | 一般的な確認（業務影響なし、誤操作防止程度） | secondary 主 CTA |
  | `destructive` | 破壊的操作（連鎖削除を伴う） | danger 主 CTA + 影響範囲表示必須 |
- **要素構成（destructive）**: `icon（warning） / title（「○○を削除しますか？」） / description（操作の説明 + 連鎖削除件数）/ confirm-button（danger）/ cancel-button（secondary）`。
- **挙動**: 既定フォーカスは Cancel ボタン（誤って Enter で削除されないように）。HCD FB-008 / RISK-010 を実装。プロジェクト削除は配下のタスク件数・依存関係件数を必ず表示する（インタフェース設計 6.1 RISK-006 / 6.3 HO-D-008）。
- **アクセシビリティ**: Modal のフォーカストラップ・Escape キャンセルに従う。

### 4.1 個別ガイドライン

- **WCAG 準拠レベル**: WCAG 2.1 **AA** に準拠。AAA は目指さない（要件で AA 相当が暫定方針、HCD ALT-006 を継承）。
- **コントラスト比**: 通常テキスト 4.5:1、大型テキスト（18pt 以上または 14pt Bold 以上）3:1、非テキスト UI 要素 3:1（フォーカスリング・グラフィック要素）。
- **キーボード操作**:
  - **Tab 順序**: 視覚的読み順と一致。左上 → 右下を基本。
  - **フォーカスリング**: 常時表示（マウス操作中も）。`color.border.strong`（DTK-027）+ 2px 太さ（DTK-081）。
  - **モーダルのフォーカストラップ**: モーダル内でフォーカスが循環し、外に抜けない（CMP-015）。
  - **Escape キャンセル**: 全モーダル・ドロップダウンは Escape で閉じる。ConfirmDialog の Escape はキャンセル扱い。
  - **ショートカットキー**: 本リリースでは導入しない（HO-I-004。CLI 代替もなく、ガント上のドラッグキー操作も RISK-004 で未確定）。
- **スクリーンリーダー対応**:
  - **ARIA ロール**: ネイティブ要素を優先し、ARIA ロールは補完として使用（`role="dialog"` は必須）。
  - **ARIA ラベル**: IconButton（CMP-002）には `aria-label` 必須。装飾のみのアイコンには `aria-hidden="true"`。
  - **ARIA ライブリージョン**: Toast（CMP-021）成功は `polite`、エラーは `assertive`。EmptyState の状態変化（フィルタ適用で空に変わった等）は `polite` で通知。
  - **画像・アイコンの alt**: 装飾目的は空 alt、情報目的は説明 alt。本ツールは情報目的のアイコンが多い（期限超過マーク・親タスクマーク等）ため、これらには適切な alt / aria-label を付与する。
- **可読性**:
  - **最小フォントサイズ**: 12px（DTK-047）。それ以下は使わない。
  - **行間**: 本文は 1.5〜1.7（DTK-045〜DTK-047）。
  - **段落幅**: 日本語の本文では 1 行 40〜50 文字を目安。タスク説明・プロジェクト説明の表示で適用。
- **タッチターゲット**: 本ツールはデスクトップ専用（NFR-003）のため、タッチターゲットの最小寸法（44×44px）は適用対象外。ただし、マウス精度の補助としてリサイズハンドル等のヒット領域は最低 8px 以上を確保（A11Y-004 と整合）。
- **動きへの配慮**:
  - `prefers-reduced-motion: reduce` を尊重。
  - 自動再生・自動切替は導入しない。
  - 点滅は禁止（WCAG 2.3.1）。
- **音の扱い**: 本ツールは音声情報を扱わない。通知音にも依存しない設計（HCD A11Y で対象外）。
- **言語切替**: 本ツールは日本語単一。`<html lang="ja">` 相当の設定を実装側で固定する（→ HO-I-002）。RTL 対応・多言語対応は持たない。

## 5. ブランド運用ルール

本ツールは独立した製品ブランドを持たない**業務ツール**である。ブランド運用ルールは最小限とし、視覚的一貫性のみを担保する。

### 5.1 ロゴ

本ツールはロゴを持たない（製品名「WBS 管理ツール」のテキストのみをヘッダに表示）。専用ロゴが将来導入された場合の運用ルールは別途定義する（HO-I-005）。

### 5.2 画像・イラスト・アイコン

- **写真**: 本ツールでは使用しない。
- **イラスト**: 本ツールでは使用しない（EmptyState の装飾も含めて使わない方針 — 業務ツールとしての簡素さを優先）。
- **アイコン**:
  - 線画ベース（アウトラインスタイル）を統一採用する。
  - 太さは 1.5〜2px 相当を基準。
  - 用途別:
    - 操作（追加・編集・削除・閉じる・保存・出力）
    - 状態（成功・警告・期限超過・ロック / 親タスク）
    - ナビゲーション（戻る・展開 / 折りたたみ）
  - アイコンライブラリの選定は実装工程（→ HO-I-005）。候補としては Lucide / Heroicons（Outline）等の線画系。
  - 装飾用アイコンには `aria-hidden="true"`、情報伝達用アイコンには `aria-label` を付与（A11Y）。

### 5.3 文言トーン

- **基本トーン**: 「です・ます」体。フォーマル過ぎず、業務ツールに適した中性的な丁寧表現。
- **業務用語の統一**:
  - 「タスク」「プロジェクト」「依存関係」「ガントチャート」「期限超過」「進捗」「親タスク」「子タスク」「先行」「後続」は要件定義書の用語に統一する。
  - 「ユーザー」「アカウント」「ログイン」等の認証関連用語は使わない（要件で認証なし）。
- **エラーメッセージの方針**:
  - ユーザーに責任を帰さない書き方（HCD FB-007 を継承）。
    - 例: 「入力が間違っています」→「日付の形式（YYYY-MM-DD）で入力してください」
    - 例: 「保存できません」→「タスク名を入力してください」
  - 何が起きたか・次に何をすべきかを必ず含める。
  - ERR-005 / ERR-006 では相関 ID（短縮形）を併記する（インタフェース設計 4.4 を継承）。
- **マイクロコピーの最終表現**: ボタンラベル・プレースホルダ・確認ダイアログ文言・ツールチップは HO-I-006 で確定する。
- **禁止用語**: 差別的表現・誤解を招く表現は使用しない。本ツールは業務ツールのため該当する局面はほぼないが、原則として明記する。

### 5.4 禁止事項

- 装飾的なイラスト・絵文字を UI に混入させない（ツールとしての中立性・業務集中性を優先）。
- アイコンを単独で意味伝達に使わない（必ずラベルまたは aria-label と併用）。
- 色のみで意味を伝えない（A11Y-001 を継承）。
