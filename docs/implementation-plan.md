### 1.2 含むもの / 含まないもの

**含むもの**

- 単一 Node.js プロセス（フロント配信 + REST API + SQLite アクセス）
- フロント自前 SVG ガント描画・クライアント PDF 生成
- SQLite 単一ファイル永続化（スキーマ移行機構含む）
- 全 UI（UI-001〜007）/ 全 API（API-001〜013）の実装
- 単体テスト・E2E テスト・性能実測（500 タスク × 1,000 依存関係）

**含まないもの**

- 認証・認可・マルチユーザー対応・ネットワーク越し利用
- 既存システム移行・外部連携・通信暗号化
- 自動バックアップ・監視基盤連携・CI/CD インフラ整備（GitHub Actions レベルは含む）
- 詳細な配布インストーラ（ローカル `npm run` 起動を前提）

### 1.4 前提・仮定

- 利用者は技術的素養があり、`npm run` 等のローカル起動操作を許容する（アーキ設計 1.3）。
- フロント・バックエンドとも **TypeScript** を採用する（型による契約共有 + クライアント／サーバの VR 共有のしやすさを優先。RISK-001 緩和。本計画書で確定）。
- 具体ライブラリ（フレームワーク / ORM / PDF / テストランナー）は T-002 で確定する。本計画書は「ライブラリに依存しないタスク粒度」で記述し、具体名は推奨候補のみ示す。
- 設計書の `OPEN-01〜16` は未決事項として §11 に再掲し、各タスクの前提を明示する。

### 5.1 Release Blocker（再掲）

以下が 1 件でもあればリリース不可。

- Linter Error / 型エラー
- Critical 不具合 / 未承認の High 不具合
- 主要 E2E（E2E-01〜08 のいずれか）失敗
- データ破壊（連鎖削除の取りこぼし・親派生値の不整合・FK 違反）
- 権限逸脱 ※本システムは認証なしのため該当しない設計だが、`localhost` 外からのアクセス遮断（CORS / Same-Origin）が機能していない場合は Blocker 扱い
- 非機能要件未達（NFR-001 を満たさない / NFR-002 規模で動作しない）
- ログ・監視不足による運用不能（ERR-005/006 が相関 ID なしで発生する等）

## 12. 進め方チェックリスト

§3 タスク一覧 / §4 実装順序を **実行手順** に翻訳したビュー。実装着手者はこのチェックリストを上から順に埋めていく。

階層は **Phase（レイヤ大粒度） → Step（1 commit = 1 PR 単位） → Task（§3 の `T-NNN` を引用）** の 3 段。Step 末尾には必ず `動作確認 / 品質ゲート / commit` の 3 点を含める。実装タスクと同一 PR で「主要観点の単体テスト」を含めることを必須とし、横串の網羅テスト（T-067〜T-072）は各 Phase 末の独立 Step に置く。

### 12.1 凡例

- `Phase N: ...` … レイヤ単位の大区切り。Phase 着手前ゲート（OPEN 確定など）はこの直下に明記する。
- `Step N.M: ...` … 1 commit / 1 PR に収まる作業塊。
- `T-NNN: ...` … §3 の Task ID。1 行 1 ID で記載し、§3 表と双方向トレース可能にする。
- `動作確認:` … 対象レイヤに応じた最小限の挙動確認。
- `品質ゲート:` … §5 の該当行（Formatter / Linter / 型 / Unit / E2E）を Step 単位で具体化したもの。
- `commit:` … プロジェクトの git log 規約（`{範囲}: {内容}` / 日本語）に合わせたメッセージ例。

### 12.3 Step 完了の運用ルール

- 1 Step = 1 commit / 1 PR を超えないこと。超えそうなら Step を分割する。
- 各 Step は `動作確認 / 品質ゲート / commit` の 3 点を必ず埋める。プロジェクト都合で動作確認が不要な Step（ドキュメント整備など）でも、その旨を確認内容として記載する。
- 横串テスト Step（2.7 / 3.8 / 4.7 / 5.7 / 6.12）は §3.8 の「各実装タスクと同一 PR で主要観点の単体テストを含める」前提を覆さない。Phase 終端での網羅整備として位置づける。
- OPEN ゲートが未確定のまま着手しない（特に Phase 2 の OPEN-03/04, Phase 3 Step 3.5 の OPEN-01/02, Phase 4 Step 4.3 の OPEN-09）。
